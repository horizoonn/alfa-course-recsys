# Альфа-Курс — интерфейс

React + TypeScript + Vite. Необязательная анкета, до трёх карточек с причинами и следующим действием, холодный старт и сообщение об отсутствии совпадений.

## Запуск

```bash
cd frontend
npm ci
npm run dev
```

Открыть `http://localhost:5173`. Мок включён по умолчанию; `.env` не обязателен. Для изменения настроек скопировать `.env.example` в `.env`. Dev-сервер доступен в локальной сети через адрес, показанный Vite.

## Проверки

```bash
npm test
npm run build
npm run lint:api
```

Тесты используют Node.js 20+, встроенный `node:test`, установленный TypeScript и серверный рендер React. Они проверяют карточки, ограничения, ошибки, запросы клиента и моки. Для браузерной проверки запустить `npm run preview` после сборки.

## Подключение к API

[OpenAPI](../api/openapi.yaml) — источник формы запросов и ответов.

| Метод | Назначение |
|---|---|
| `GET /api/meta` | Пять справочников анкеты |
| `POST /api/recommendations` | Профиль либо `demo_profile_id`; `{}` — холодный старт |
| `GET /api/demo-profiles` | Синтетические профили P01–P10 |
| `GET /api/health` | Готовность API и подготовленного каталога |

По умолчанию фронтенд работает с реальным API (`VITE_USE_MOCK=false`). В разработке `/api/*` проксируется на `http://127.0.0.1:8080` (переопределяется через `VITE_PROXY_TARGET`). В продакшене тот же путь проксирует сервис на Render, поэтому CORS на Go-сервере не нужен; для размещения на другом origin задать `VITE_API_BASE` с префиксом `/api`. Переменные `VITE_*` публичны и не подходят для секретов.

В TypeScript типы заданы вручную. Они не заменяют проверку JSON во время выполнения; соответствие проверяется тестами и примерами контракта. Клиент читает вложенный конверт ошибок `error.code/message`; сетевой сбой отличается от пустой выдачи.

## Запуск внутри Telegram (через бота)

Mini App запускается ботом из папки [`bot/`](../bot/README.md). URL в BotFather
вводить не нужно: бот регистрирует кнопку меню и inline-кнопку через Bot API.

1. Собрать фронт: `npm run build`.
2. Скопировать сборку в сервис бота: `cd ../bot && npm run sync-web`
   (Render собирает только каталог `bot`, поэтому `bot/web` коммитится).
3. Запушить: Render пересоберёт сервис, адрес Mini App —
   `https://<service>.onrender.com/` (подставляется из `RENDER_EXTERNAL_URL`).
4. В Telegram открыть чат с ботом → `/start` → кнопка «Открыть Альфа Курс».

Подробности и переменные окружения — в [`bot/README.md`](../bot/README.md).

Вне Telegram SDK недоступен — интерфейс это обрабатывает
(`isTelegram=false`), никаких ошибок не возникает.

## Сценарии

- Выбор демо-профиля заполняет анкету. Ручная правка переключает её на собственный профиль. Возврат из выдачи сохраняет последний выбор.
- Карточки поддерживают `article`, `course`, `document`, `term`, `calculator`, `podcast`, `webinar`. Уроки остаются внутри курса.
- Доступ: `free`, `subscription`, `paid`, `unknown`. Причины содержат `code` и `text`, ограничения — `code` и `message`.
- Описание и ссылка могут быть `null`. При отсутствующей ссылке предлагается изменить подборку; фиктивной ссылки нет.
- P07 — холодный старт; P08 — подписка; P09 — отсутствие совпадений. P10 сообщает `HISTORY_UNAVAILABLE`: история обучения пока не моделируется.

Мок в `src/api/mock.ts` имитирует правила `4T + 2M + S + E + I` только для разработки UI. При отсутствии кандидатов по выбранной задаче он возвращает пустой результат. Это не доказательство качества подбора на реальном каталоге.

## Telegram

Тот же интерфейс может открываться как Mini App. `src/hooks/useTelegram.ts` загружает SDK асинхронно; его недоступность не блокирует обычную веб-страницу. Для Mini App нужны HTTPS-размещение и настройка запуска через бота. Данные Telegram не передаются в запросе рекомендаций и не используются как подтверждение личности или прав доступа.

## Демо без бэкенда

Сборка с мок-данными (для показа интерфейса до запуска Go API):

```bat
set VITE_USE_MOCK=true&& npm run build
```

Если API недоступен при выключенном моке, интерфейс не падает: App.tsx автоматически
переключается на демонстрационные данные и показывает предупреждение вверху экрана.
То есть демо проходит даже при лежащем бэкенде.

## Стабильный адрес для демо

Бесплатные туннели (localhost.run, serveo, trycloudflare) рвут сессию и выдают новый адрес —
если регистрировать этот адрес в Telegram, Mini App «отваливается» через несколько минут.
Поэтому в Telegram регистрируется постоянный адрес Render, а туннель нужен только
для доступа к локальному API:

1. На Render в сервисе бота задать `ADMIN_TOKEN` и `KEEPALIVE=1`;
   `WEBAPP_URL` не задавать — он подставится из `RENDER_EXTERNAL_URL`.
2. В `bot/.env` добавить `ADMIN_URL=https://<service>.onrender.com` и тот же `ADMIN_TOKEN`.
3. Запустить из корня репозитория: `node scripts\\tunnel.mjs` (по умолчанию порт 8080).
   Скрипт держит соединение, при обрыве переподключается и сам публикует новый адрес
   в Render через `POST /__admin/target`.

Держи запущенными: Docker (postgres + app) и туннель. `npm run preview` больше не нужен —
SPA отдаёт Render. Если API недоступен, интерфейс показывает демо-данные с плашкой.
