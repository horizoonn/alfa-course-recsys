# Альфа-Курс — интерфейс

React, TypeScript и Vite. Свободный ввод, необязательная анкета, демо-профили, до трёх карточек с причинами и ссылки на материалы. По умолчанию интерфейс обращается к настоящему API.

## Запуск через Docker

Полная инструкция — в [корневом README](../README.md). После настройки `.env` и размещения backup:

```bash
docker compose up -d --wait
```

Открыть http://localhost:5173. Фронтенд запускается после готовности `app`. Nginx раздаёт страницу и направляет `/api/...` на `app:8080` внутри Docker.

## Локальная разработка

Нужны Node.js 20+ и запущенный бэкенд:

```bash
cd frontend
npm ci
npm run dev
```

Открыть http://localhost:5173. Vite берёт порт Go-приложения из `APP_PORT` в корневом `.env`. Если адрес другой, скопировать `frontend/.env.example` в `frontend/.env` и заполнить `VITE_PROXY_TARGET`, например `http://localhost:18080`.

`VITE_API_BASE=/api` сохраняет запросы на том же origin. `VITE_USE_MOCK=true` явно включает синтетические данные для разработки UI. Значения `VITE_*` попадают в клиентскую сборку; секреты в них не хранить. Docker-сборка использует настоящий API независимо от локальных файлов `.env`.

## Проверки

```bash
npm test
npm run build
npm run lint:api
```

Тесты проверяют карточки, ошибки, запросы клиента, настоящий API по умолчанию и моки. Проверка с реальным бэкендом выполняется отдельно через браузер.

## Контракт

[OpenAPI](../api/openapi.yaml) описывает операции:

- `GET /api/meta` — справочники анкеты.
- `GET /api/demo-profiles` — профили P01–P10.
- `POST /api/recommendations` — `query` с необязательным профилем либо `demo_profile_id`, пустой объект для стартовой подборки.
- `GET /api/health` — готовность Go-приложения.

Форма заполняется из ответа API. Ручная правка демо-профиля переключает запрос на собственный профиль. Типы карточек: article, course, document, term, calculator, podcast и webinar. Причины, включая `content_match`, отображаются текстом из ответа. Ограничения и отсутствие совпадений показываются пользователю; отсутствие ссылки даёт действие «Изменить подборку».

P07 проверяет пустой профиль, P08 — только задачу продвижения, P09 — зарубежные рынки, P10 — синтетическую историю. Стартовая подборка работает без локальной ручной разметки. Для истории P10 нужен отдельный рабочий файл разметки. Моки имеют собственные демонстрационные сценарии и не подтверждают качество реальных рекомендаций.

## Пустая анкета и неполный профиль

«Пропустить анкету» запрашивает общую стартовую подборку. Если задача не выбрана, API учитывает подтверждённые совпадения остальных полей либо возвращает общую подборку с пояснением. Указанные стадия и опыт пока не влияют на выдачу: этих признаков нет у материалов.

Сообщения из `limitations` отображаются рядом с карточками. Если подходящих материалов нет, показывается пустое состояние с возможностью изменить запрос. Сетевая ошибка отображается отдельно.

Поле задачи принимает до 1000 символов. Ввод текста сбрасывает выбранную тему и демо-профиль; выбор темы или демо очищает текст. Формат помощи доступен сразу, остальные поля — в блоке «Уточнить контекст». После возврата из результатов и при повторе ошибки запрос сохраняется.

Запрос отправляется кнопкой. `AbortController` отменяет предыдущий запрос; устаревший ответ не заменяет новую подборку. Неясный ввод показывает просьбу уточнить задачу, техническая ошибка — возможность повторить запрос. В режиме моков текстовый поиск явно недоступен: он требует настоящего backend.

В интерфейсе нет ручных оценок или отметок завершения. Открытия ссылок не записываются; личная cookie-сессия не создаётся.

В блоке «История из базы Альфа-Курса» доступны H01–H03 — обезличенные сценарии реального обучения и оценок. Их можно совместить с текстом или анкетой. Результаты помечены выбранным сценарием; личные действия браузера к нему не подмешиваются. Чтобы снова учитывать собственные действия, выберите «Без сценария из базы». В режиме моков H-сценариев нет.

Под карточкой автоматически подбираются до двух материалов для углубления. Блок показывает название, тип, условия доступа и объяснение: например, какой раздел программы курса продолжает тему исходной статьи. Если подходящего продолжения нет, блок скрыт. При технической ошибке доступна повторная загрузка дополнительных материалов.

`Deepening.tsx` обращается к `/api/deepening` отдельно от основного подбора и отменяет устаревшие запросы. Передаются исходный запрос, выбранный сценарий истории и ключи текущей подборки, чтобы сохранить ограничения и избежать повторов. Переход открывает страницу материала без записи события. В режиме моков углубление не показывается.

## Telegram

Интерфейс работает как обычная веб-страница и может открываться как Mini App. SDK загружается асинхронно. Для Telegram нужны HTTPS-размещение и настройка запуска через бота. Данные Telegram не используются для подтверждения личности или прав доступа к материалам.

## Размещение Mini App



Бесплатные туннели (localhost.run, serveo, trycloudflare) рвут сессию и выдают новый адрес —
если регистрировать этот адрес в Telegram, Mini App «отваливается» через несколько минут.
Поэтому в Telegram регистрируется постоянный адрес Render, а туннель нужен только
для доступа к локальному API:

1. На Render в сервисе бота достаточно `BOT_TOKEN`: адрес Mini App берётся из
   `RENDER_EXTERNAL_URL`, `KEEPALIVE` включён по умолчанию.
2. Запустить из корня репозитория: `node scripts\\tunnel.mjs` (по умолчанию порт 8080).
   Скрипт держит соединение, при обрыве переподключается и после каждого
   переподключения публикует новый адрес в GitHub — в ветку `tunnel`,
   файл `bot/tunnel-url.txt`.
3. Сервис на Render каждые две минуты перечитывает этот файл и переключает `/api`
   на актуальный туннель. Панель Render и переменные окружения не нужны.

Держи запущенными: Docker (postgres + app) и туннель. `npm run preview` больше не нужен —
SPA отдаёт Render. Если API недоступен, интерфейс показывает ошибку и предлагает повторить запрос.
