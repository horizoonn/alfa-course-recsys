# Альфа-Курс — интерфейс

React + TypeScript + Vite. Выбор задачи и формата помощи, необязательные уточнения, до трёх карточек с причинами и следующим действием. Работает в браузере и Telegram Mini App.

## Запуск

```bash
cd frontend
npm ci
npm run dev
```

Открыть `http://localhost:5173`. По умолчанию включён реальный API; `.env` не обязателен. Для изменения настроек скопировать `.env.example` в `.env`. Dev-сервер доступен в локальной сети через адрес, показанный Vite. Нужен Node.js 22+.

## Проверки

```bash
npm test
npm run build
npm run lint:api
```

Тесты используют Node.js 20+, встроенный `node:test`, установленный TypeScript и серверный рендер React. Они проверяют карточки, ограничения, ошибки, запросы клиента и моки. Для браузерной проверки запустить `npm run preview` после сборки.

## Подключение к API

[OpenAPI](../api/openapi.yaml) — источник формы запросов и ответов.

| Метод | Назначение |
|---|---|
| `GET /api/meta` | Пять справочников анкеты |
| `POST /api/recommendations` | Профиль либо `demo_profile_id`; `{}` — холодный старт |
| `GET /api/demo-profiles` | Синтетические профили P01–P10 |
| `GET /api/health` | Готовность API и подготовленного каталога |

По умолчанию фронтенд работает с реальным API (`VITE_USE_MOCK=false`). В разработке `/api/*` проксируется на `http://127.0.0.1:8080` (переопределяется через `VITE_PROXY_TARGET`). В продакшене тот же путь проксирует сервис на Render, поэтому CORS на Go-сервере не нужен; для размещения на другом origin задать `VITE_API_BASE` с префиксом `/api`. Переменные `VITE_*` публичны и не подходят для секретов.

В TypeScript типы заданы вручную. Клиент дополнительно проверяет структуру JSON перед отображением; некорректный ответ показывает ошибку. Поддерживаются вложенный конверт `error.code/message` и ошибки прокси 502/503/504. Запрос ограничен 25 секундами, включая чтение ответа. Сетевой сбой отличается от успешного ответа с пустой выдачей.

## Запуск внутри Telegram (через бота)

Mini App запускается ботом из папки [`bot/`](../bot/README.md). URL в BotFather
вводить не нужно: бот регистрирует кнопку меню и inline-кнопку через Bot API.

1. Собрать фронт: `npm run build`.
2. Скопировать сборку в сервис бота: `cd ../bot && npm run sync-web`
   (Render собирает только каталог `bot`, поэтому `bot/web` коммитится).
3. Запушить: Render пересоберёт сервис, адрес Mini App —
   `https://<service>.onrender.com/` (подставляется из `RENDER_EXTERNAL_URL`).
4. В Telegram открыть чат с ботом → `/start` → кнопка «Открыть Альфа Курс».

Подробности и переменные окружения — в [`bot/README.md`](../bot/README.md).

Вне Telegram SDK недоступен — интерфейс это обрабатывает
(`isTelegram=false`), никаких ошибок не возникает.

## Сценарии

- Выбор демо-профиля заполняет анкету. Ручная правка переключает её на собственный профиль. Возврат из выдачи сохраняет последний выбор.
- Карточки поддерживают `article`, `course`, `document`, `term`, `calculator`, `podcast`, `webinar`. Уроки остаются внутри курса.
- Доступ: `free`, `subscription`, `paid`, `unknown`. Причины содержат `code` и `text`, ограничения — `code` и `message`.
- Описание и ссылка могут быть `null`. При отсутствующей ссылке предлагается изменить подборку; фиктивной ссылки нет.
- P07 — холодный старт; P08 — только задача. Состав P09 и P10 определяется реальным API: отсутствие совпадений для P09 не гарантируется, история P10 зависит от разметки бэкенда. В моке P09 проверяет пустую выдачу, а P10 сообщает `HISTORY_UNAVAILABLE`.

Мок в `src/api/mock.ts` имитирует правила `4T + 2M + S + E + I` только для разработки UI. При отсутствии кандидатов по выбранной задаче он возвращает пустой результат. Это не доказательство качества подбора на реальном каталоге.

## Telegram

Тот же интерфейс может открываться как Mini App. `src/hooks/useTelegram.ts` загружает SDK асинхронно одним общим запросом и инициализирует его один раз. Недоступность SDK не блокирует обычную веб-страницу. Пустой `initData` не считается запуском внутри Telegram. На выдаче подключается системная кнопка «Назад», ссылки открываются через SDK. Для Mini App нужны HTTPS-размещение и настройка запуска через бота. Данные Telegram не передаются в запросе рекомендаций и не используются как подтверждение личности или прав доступа.

## Демо без бэкенда

Сборка с мок-данными (для показа интерфейса до запуска Go API):

```bat
set VITE_USE_MOCK=true&& npm run build
```

В рабочей сборке используются только ответы реального API. Сетевой сбой,
тайм-аут или ответ 502/503/504 показывается как ошибка с возможностью
повторить запрос. Рекомендации не подменяются учебными данными.
Мок доступен только при явной сборке с `VITE_USE_MOCK=true`, отмечен
предупреждением и не открывает фиктивные ссылки.

## Проверка перед показом

1. Выбрать задачу и формат помощи, получить карточки и открыть материал.
2. Нажать «Изменить запрос»: выбранные значения должны сохраниться.
3. Пропустить анкету: UI отображает фактический ответ API, в том числе пустой.
4. Проверить недоступный API: видна ошибка, учебные карточки не появляются.
5. Восстановить API и повторить запрос: появляется выдача из реального каталога.
6. Открыть внутри Telegram: проверить имя, открытие ссылок и системную кнопку «Назад».
7. Проверить ширину 320–390 px, тёмную тему и длинные названия материалов.

После изменений обязательно выполнить `npm test`, `npm run build` и
`cd ../bot && npm run sync-web`. Папка `bot/web` содержит сборку для Render;
изменения только в `frontend/src` не обновляют размещённый Mini App.

## Стабильный адрес для демо

Бесплатные туннели (localhost.run, serveo, trycloudflare) рвут сессию и выдают новый адрес —
если регистрировать этот адрес в Telegram, Mini App «отваливается» через несколько минут.
Поэтому в Telegram регистрируется постоянный адрес Render, а туннель нужен только
для доступа к локальному API:

1. На Render в сервисе бота достаточно `BOT_TOKEN`: адрес Mini App берётся из
   `RENDER_EXTERNAL_URL`, `KEEPALIVE` включён по умолчанию.
2. Запустить из корня репозитория: `node scripts\\tunnel.mjs` (по умолчанию порт 8080).
   Скрипт держит соединение, при обрыве переподключается и после каждого
   переподключения публикует новый адрес в GitHub — в ветку `tunnel`,
   файл `bot/tunnel-url.txt`.
3. Сервис на Render каждые две минуты перечитывает этот файл и переключает `/api`
   на актуальный туннель. Панель Render и переменные окружения не нужны.

Держи запущенными: Docker (postgres + app) и туннель. `npm run preview` больше не нужен —
SPA отдаёт Render. Если API недоступен, интерфейс показывает ошибку и предлагает повторить запрос.
