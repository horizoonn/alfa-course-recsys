# Backend

Go API с каталогом в памяти. PostgreSQL хранит исходный каталог и историю Альфа-Курса; Python готовит текстовые оценки и обслуживает поиск по свободному запросу. Общий запуск описан в [корневом README](../README.md).

## Подготовка каталога

1. Go читает семь видов материалов в одной read-only транзакции с `RepeatableRead`.
2. SQL-модели преобразуются в `domain.Material`. Ключ состоит из вида и UUID; уроки остаются внутри курса.
3. Правила связывают проверенные темы, теги и категории с задачами, форматами помощи и отраслями. Ручная разметка применяется при совпадении ключа и хеша названия.
4. Экспортёр собирает поисковое представление из названий, описаний, метаданных, текстовых блоков, названий вложений и доступных уроков курса.
5. Python рассчитывает TF-IDF со Snowball для русского языка. Веса групп: метаданные — 0.7, основной текст — 0.3, подписи и ссылки — до 0.05. Рекламные фрагменты не влияют на поиск.
6. При запуске API проверяет версию, отпечаток и полноту оценок. Отсутствующий или устаревший файл блокирует запуск HTTP. После загрузки каталог и H-сценарии остаются в памяти, пул PostgreSQL закрывается.

## Подбор по задаче

Сначала исключаются скрытые материалы и завершённые записи из подключённой демо-истории. Допускаются материалы с direct/broader-разметкой или текстовым совпадением от 0.1.

Проверенные direct-соответствия идут первыми. Затем учитываются текстовая релевантность и подтверждённые совпадения профиля. Неизвестные признаки не дают бонусов. Платность и рейтинг не повышают позицию. Повторяющиеся карточки с одинаковыми названием и ссылкой не выдаются.

Объяснения формируются из сигналов, которые участвовали в подборе. Полные тексты и внутренние баллы остаются на сервере.

## Холодный старт и неполный профиль

Без выбранной задачи используется отдельная общая подборка:

1. Если заполненные поля дают подтверждённые совпадения, соответствующие материалы выбираются первыми. Совпадение формата имеет вес 2, остальные признаки — по 1; текстовая оценка используется для дополнительного упорядочивания.
2. Оставшиеся места заполняются из проверенного ручного starter.
3. Если мест всё ещё не хватает, выбираются бесплатные материалы со ссылками по трём темам: запуск бизнеса, финансы и привлечение клиентов. Сначала берётся по одному материалу на тему, затем — оставшиеся подходящие кандидаты.

Для пустого профиля без подходящей истории режим ответа — `starter`; если общую подборку изменили темы истории — `personalized`; для неполного без задачи — `fallback`. Причины общей подборки не утверждают, что известны интересы или уровень пользователя. Если совпадений профиля нет, это указано в `limitations`.

Стадия бизнеса и опыт пока не размечены у материалов. Профиль только с такими полями получает общую подборку, а не сортировку каталога по UUID. Запрос с выбранной задачей без совпадений возвращает пустой `items`; посторонние материалы к нему не добавляются.

При выбранной задаче B0 использует тематические соответствия и ключи без текстового и персонального ранжирования. Для пустого профиля у B0 и основного алгоритма одна стартовая подборка.

## Локальная разметка

`data/catalog_curation.json` хранит проверенные привязки, starter и синтетические события P10. Реальные ключи и выгрузки не публикуются. В [примере](../data/catalog_curation.example.json) ID вымышленные: автоматическая стартовая подборка продолжает работать, а P10 сообщает `HISTORY_UNAVAILABLE`.

При изменении названия ручное правило перестаёт применяться до повторной проверки. Отсутствие указанного файла разметки — ошибка конфигурации. Пустой `CATALOG_CURATION_PATH` отключает ручную разметку. Docker сам создаёт рабочий файл из примера, если его ещё нет.

## Локальный запуск без Docker для приложения

Нужны Go 1.27.0+, Task, Python 3.12–3.13, uv и восстановленная PostgreSQL. Из корня проекта, после настройки `.env`:

```bash
cp -n data/catalog_curation.example.json data/catalog_curation.json
task openapi:generate
(cd backend && go run -mod=readonly ./cmd/catalog-export --documents-only)
uv sync --project ranking --frozen
uv run --project ranking --frozen python ranking/prepare_search.py data/ranking_catalog.json
# В отдельном терминале из корня репозитория:
SEARCH_INDEX_PATH="$PWD/data/search" uv run --project ranking --frozen uvicorn search_api:app --app-dir ranking --host 127.0.0.1 --port 8090 --no-access-log
# В другом терминале:
task run
```

Приложение читает `.env` из текущего каталога либо из родительского. Переменные окружения имеют приоритет. Изменение исходных данных или формулировок задач требует повторного экспорта, подготовки оценок и перезапуска приложения.

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Подключение к PostgreSQL; обязательна |
| `HTTP_ADDR` | HTTP-адрес; по умолчанию `127.0.0.1:8080` |
| `STARTUP_TIMEOUT` | Подключение и загрузка; по умолчанию `30s` |
| `SHUTDOWN_TIMEOUT` | Завершение запросов; по умолчанию `10s` |
| `CATALOG_CURATION_PATH` | Разметка; по умолчанию `../data/catalog_curation.json` из `backend/` |
| `TEXT_SCORES_PATH` | Текстовые оценки; по умолчанию `../data/ranking_text_scores.json` из `backend/` |

## Сравнение с baseline

После подготовки текстовых оценок можно экспортировать обе выдачи:

```bash
(cd backend && go run -mod=readonly ./cmd/catalog-export --output ../data/ranking_comparison.json)
uv run --project ranking --frozen python ranking/evaluate.py data/ranking_comparison.json
```

Без независимой разметки команда сохраняет варианты рекомендаций, но не выдаёт метрик качества. Оценки передаются через `--labels /path/to/labels.json`: профиль → ключ материала → релевантность 0–2. Неразмеченные материалы не считаются нерелевантными. Данные и результаты сравнения остаются локальными.

## Свободный запрос

`recommendation/search.go` задаёт узкий интерфейс поиска и применяет правила выдачи. `client/textsearch/client.go` отправляет только запрос, режим и отпечаток каталога; по умолчанию таймаут — 2 секунды. Ответ проверяется на версию, ключи, дубликаты и конечные оценки от 0 до 1. Несовпадение каталога и техническая ошибка дают `503`, а не общую подборку вместо ответа на конкретную задачу.

Python загружает индекс один раз в lifespan FastAPI. `ranking/prepare_search.py` сохраняет поколения индекса и атомарно переключает `current.json`; `search_index.py` проверяет контрольные суммы и обслуживает запросы. При изменении каталога или подготовки данных индекс перестраивается. Неактивные поколения можно удалить после остановки поискового сервиса; рабочее поколение указано в `current.json`.

Для TF-IDF сохраняются словарь, IDF и разреженная матрица. Сохраняются короткие аббревиатуры ИП, ИИ, HR и IT. Неизвестные содержательные слова и неподдерживаемые отрицания обрабатываются консервативно. Распознаются ограничения «только бесплатно» и «без курсов»; остальные сложные отрицания требуют уточнения.

Для E5 используются локальные ONNX-веса `intfloat/multilingual-e5-small`, закреплённая ревизия и SHA-256 в `ranking/semantic.py`. Векторы имеют 384 координаты; для запроса и документа применяются префиксы `query:` и `passage:`. E5 получает название, краткое описание и метаданные карточки; полный текст по-прежнему участвует в TF-IDF. Во время HTTP-запроса модель не скачивается. Один процесс Python и ограничение CPU-потоков избегают дублирования модели несколькими workers.

Ранжирование свободного запроса начинается с поисковой оценки. Подтверждённые совпадения профиля дают множитель `1 + 0.1 × (2M + S + E + I + H)`. Приоритет direct-разметки восьми готовых задач сюда не переносится. Затем применяются доступность, ограничения запроса, завершение и удаление дублей. Платность не повышает балл.

| Настройка | Назначение |
|---|---|
| `TEXT_SEARCH_URL` | Адрес Python; локально `http://127.0.0.1:8090`, в Compose `http://text-search:8090` |
| `TEXT_SEARCH_MODE` | `tfidf`, экспериментальные `e5` или `rrf` |
| `TEXT_SEARCH_TIMEOUT` | Таймаут Go-клиента, пример `2s` |
| `SEARCH_ENABLE_SEMANTIC` | Подготавливать и загружать E5, по умолчанию в примере `false` |
| `SEARCH_MODEL_TIMEOUT` | Максимальное время скачивания, пример `120` секунд |

Сравнение из локального Go: `go run ./cmd/catalog-export --queries ../data/queries.example.json --output ../data/ranking_query_comparison.json`. Поисковый сервис должен быть запущен. Это сравнение TF-IDF/E5/RRF для свободных запросов; B0 остаётся тематическим baseline для фиксированных задач.

Текстовая часть: словарный TF-IDF по группам полей и символьный `char_wb` 3–5 по карточкам с ограничением 50 000 признаков. Словарный и символьный сигналы объединяются; затем для каждого кандидата проверяются предмет запроса и подтверждение цели. Для определений словарные материалы сохраняют обычный приоритет; для запросов на действие их балл понижается. Семантический канал рассчитывается независимо от словарного допуска, с собственными порогами уверенности. Пороги пока инженерные и не подтверждены независимой разметкой.

`ranking/intent.py` хранит разбор намерения, `ranking/text.py` — нормализацию. В диагностике сохраняются положительная часть запроса, поисковый текст, распознанные цели, ограничения и исправления. E5 получает тот же уточнённый поисковый текст, что словарный канал; символьный канал использует положительную формулировку. `SearchResult` сохраняет отдельные word/character/semantic оценки, чтобы различать вклад алгоритмов. Модель и её оценки не подменяют проверку ограничений.

## Исходная история Альфа-Курса

- `internal/repository/postgres/platformhistory` читает прохождение курсов, завершения уроков и последние оценки в read-only транзакции.
- `internal/service/platformhistory` сопоставляет их с доступным каталогом и выбирает обезличенные сценарии H01–H03. Исходные UserId остаются внутри сервера; публичный `GET /api/history-profiles` отдаёт описание и счётчики.
- `history_profile_id` можно совместить с запросом или своим профилем. `demo_profile_id` используется отдельно.
- Завершённые курсы и материалы с оценками 1–2 исключаются; начатое обучение и оценки 4–5 дают ограниченный тематический сигнал. История не обязательна для работы.
- Собственного журнала посетителя, cookie-сессий и API записи действий нет. Пул PostgreSQL закрывается после чтения данных при запуске.

Документация используемых механизмов: [TF-IDF](https://scikit-learn.org/1.7/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html), [жизненный цикл FastAPI](https://fastapi.tiangolo.com/advanced/events/), [модель E5](https://huggingface.co/intfloat/multilingual-e5-small), [FastEmbed](https://github.com/qdrant/fastembed).

H01 выбирается по числу завершённых курсов, H02 — по начатым, H03 — по оценкам 1–2 и 4–5. Для каждого используется вся подходящая история; 3 нейтральна. Низкая оценка урока не исключает целый курс. При равенстве выбор стабилен, один пользователь не занимает два сценария. Снимок обновляется при запуске. Подключение текущего аккаунта Альфа-Курса требует отдельной интеграции авторизации.

## Углубление темы

`recommendation/deepening.go` подбирает продолжение конкретного материала через узкий интерфейс `RelatedSearch`. Python `/related` сравнивает TF-IDF-векторы полного содержимого и названия; матрица сходства использует уже подготовленный индекс без загрузки отдельной модели.

Go проверяет доступность и историю. Для курса нужно совпадение предмета с содержанием конкретного доступного урока и не менее двух доступных уроков. Для статьи — более длинный текст и новый связанный раздел. Объяснение строится по фактическому названию раздела. Сам исходный материал, карточки текущей подборки и завершённые/отклонённые записи не возвращаются.

Публичный `POST /api/deepening` принимает `material_key`, необязательные `query`, `history_profile_id` или `demo_profile_id`, а также до трёх `exclude_keys`. Возвращает до двух обычных карточек с причинами `course_section` или `deepening_topic`. Ответ имеет свой `request_id` для диагностики запроса. Переходы по карточкам не записываются.


Если от прежнего прототипа в локальной БД осталась схема `recsys`, приложение её не читает и не изменяет.
